# 09 — مواصفات Wireframe للموقع التسويقي (Website Wireframes Spec)

بنفس منهجية [`03-Wireframes-Spec.md`](03-Wireframes-Spec.md) — لكل صفحة: الغرض، التخطيط (رسم نصي)، القرارات التصميمية، الحالة الفارغة، وحالة الخطأ. **Viewport: 1440px عرض (Desktop قياسي)**، المحتوى محصور داخل `max-width: 1200px` مُمركز، مع أقسام Full-Bleed تمتد 100vw كما ينص عليه `04-Design-System.md`. الاتجاه **LTR أساسي** مطابقاً لبقية المنتج؛ لا نسخة عربية RTL لهذا المنتج في هذه المرحلة (الأولوية لتغطية النسخة الإنجليزية الكاملة أولاً، تماماً كما بدأ تطبيق العميل ولوحة التحكم).

**قرار UX:** الفلترة بالفرع (راديو أحادي الاختيار وليس متعدد) — تبسيط متعمَّد لأن أغلب الزوار مهتمون بفرعهم المعتاد فقط، لا بمقارنة عروض عدة فروع معاً.

**حالة الخطأ:** فشل تحميل الفعاليات (خطأ سيرفر) → نفس رسالة الحالة الفارغة نصياً، لكن بزر "إعادة المحاولة" بدل "عرض كل الفروع" — تمييز واضح بين "لا يوجد محتوى" و"تعذّر التحميل".

## ملاحظة تصميمية عامة — الـ Header الذكي (Sticky/Transparent)

قرار واحد ينطبق على الصفحات الست جميعها: الـ Header **شفاف فوق أي Hero بصورة/فيديو** (Home, Locations, What's On)، و**أبيض صلب من البداية** فوق أي Hero نصي على خلفية بيضاء (Catering & Events, About Us, Contact) — نفس المنطق الشرطي المستخدم فعلياً في الموقع المرجعي، وليس اختياراً اعتباطياً. هذا موثّق هنا لأنه قرار UX متكرر عابر للصفحات، لا يستحق تكراره في كل قسم أعلاه.
