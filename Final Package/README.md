# Bayt Elkaram — English Project Handover

**Open [START_HERE.html](START_HERE.html) for the visual presentation.** It runs locally and links to all major exhibits. This package is an organized record of completed **product planning and UI/UX design**. It is not a finished software implementation.

## Review path

1. View the introduction and mobile screenshot gallery in `START_HERE.html`.
2. Open the customer app, admin dashboard and website HTML files in `02-Design-Artifacts` to inspect the original editable artboards.
3. Read the English documents in `01-English-Documentation`, starting with `01-Project-Overview.md`.
4. Find original images, logos, typefaces and screenshots in `03-Visual-Assets`.
5. Consult `04-Original-Planning-Reference` for the detailed Arabic source notes. It is an archival reference, not the primary English presentation.
6. Read `05-Future-Development/Implementation-Plan.md` only when discussing the next development phase; it does not describe completed code.

## Important presentation notes

- The HTML exports are **design canvases**. They are not Flutter/Next.js applications or a NestJS API.
- The three large customer/admin exports reuse the same artboard collection and differ in their saved canvas focus and a small number of board states. Keep all three if the recipient needs the exact original exports; show one at a time in a presentation.
- Maps within the artboards are illustrative previews; no live Google Maps key or operational branch/rider data is bundled.
- The branch locations, menu prices, founders, dates and similar content were used for design. Confirm them before any public product launch.
- The AI-generated imagery is labelled as such in this package. The original artwork and font licensing/usage terms should be verified for the intended external publication.
- The visual system and website structure were based closely on the supplied Roberta's Pizza reference; this is documented in the project notes.
- No PDF files are included, by the project owner's earlier preference for the editable Artifacts as the design source.

## Integrity

`MANIFEST.csv` records every deliverable content file's path, byte size and SHA-256 hash (excluding the manifest and checksum list themselves). `CHECKSUMS.sha256` can be used to confirm files were not changed after packaging. The zip archive is a copy of this folder for easier transfer.
