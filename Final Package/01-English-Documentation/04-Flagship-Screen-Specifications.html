Flagship Screen Specifications

Eighteen screens established the layout and interaction patterns used across the wider canvas: 12 in the customer application at a 390 × 844 reference viewport and six in the dashboard at 1440 × 900. The finished HTML artboards take precedence over the text-only wireframe diagrams for direction: early diagrams were drawn RTL, then corrected to English-first LTR before final UI work.

Customer application

ScreenMain compositionInteraction, empty state or exception
1. SplashCentered Bayt Elkaram wordmark on a clean white field, with minimal loading feedback.The original spec caps its appearance around 1.5 seconds; connection failure leads to the offline state rather than leaving the user on the splash.
2. HomeActive branch and notifications in the header; campaign hero; search; horizontal categories; popular items; reorder card; bottom navigation.The active branch stays visible. A first-time customer sees discovery content in place of the reorder block.
3. Branch SelectorCompact map, branch cards with distance and opening status, clear select actions.Closed branches remain visible but disabled; manual search is available if location access fails. The inserted map is an illustrative preview.
4. Branch LocatorLarger map with pins and a draggable branch-list sheet containing image, address, hours and call/directions actions.The sheet should expose all branches without losing the map context. The current artboard map is an illustrative preview.
5. MenuSticky category tabs, photo-led item rows/cards, concise description, price and quick add.Simple items can be added quickly; items with required choices open their detail screen. Empty categories suggest another category.
6. Item DetailLarge image, name, price, description, options/modifiers, notes and quantity, with a persistent Add to Cart action.The displayed total updates with selections. Unavailable modifiers are disabled before checkout.
7. CartEditable item lines, coupon entry, subtotal, delivery fee, total and a prominent checkout action.Editing reopens the item with previous options preserved. An empty cart offers a clear route back to the menu.
8. Checkout ReviewDelivery/pickup address, timing, payment choice, collapsible order details, final total and confirm action.Each key choice can be changed in context without restarting the entire checkout.
9. Live TrackingRoute/status map, order-step indicator, ETA, rider contact and help.Pickup replaces the rider map with preparation readiness. Live rider movement needs an operational location feed; the current map is a static preview.
10. ReservationBranch, date, time slots, party-size stepper and confirmation.Full slots appear disabled; when all slots are full the next available day or branch is suggested.
11. ProfileCustomer identity and loyalty tier, with shortcuts to addresses, payment methods, rewards, favourites, language and support.Loyalty status is immediately visible near the name.
12. LoyaltyProminent red points card, tier progress, redeemable rewards and points history.Rules and balances require authoritative backend data during implementation.

Shared screen-state rules

  • Loading is shown with skeletons that resemble the final layout.
  • Network or server failure uses a plain-language message and retry action.
  • Empty content includes a small illustration or concise explanation and an action to recover.
  • English uses LTR positioning and directional icons; Arabic mirrors directional elements when enabled.
  • These specifications are design intent. The accompanying PNGs and artboards show appearance; no functional prototype or deployed backend is included in the handover.
