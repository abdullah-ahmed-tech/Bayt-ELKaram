# مسارات المستخدم الكاملة (User Flows) — بيت الكرم

16 مساراً يغطون كل السيناريوهات الجوهرية للتطبيق ولوحة التحكم، شاملة الحالات الاستثنائية (Edge Cases). الترميز: `[Start]` بداية، `◇` نقطة قرار، `[End]` نهاية.

---

## قسم أ) مسارات تطبيق العملاء

### 1. مسار المستخدم الجديد — من التنزيل لأول طلب
```
[تنزيل التطبيق] → [Splash] → [اختيار اللغة] → [Onboarding: 3 شرائح]
   → [طلب صلاحية الموقع]
        ◇ سمح؟
           ├─ نعم → [تحديد أقرب فرع تلقائياً] → [الرئيسية]
           └─ لا  → [إدخال العنوان يدوياً] → [الرئيسية]
   → [تصفح المنيو كزائر] → [إضافة صنف للسلة]
        ◇ عند إتمام الطلب: يتطلب حساب
           → [تسجيل الدخول/حساب جديد] → [رقم الموبايل] → [كود OTP]
                ◇ الكود صحيح؟
                   ├─ نعم → [متابعة السلة] → [Checkout] → [نجاح الطلب]
                   └─ لا (3 محاولات) → [حظر مؤقت 5 دقائق] → [End]
```
**حالات استثنائية:**
- المستخدم يرفض صلاحية الموقع نهائياً → عرض قائمة الفروع يدوياً بدون خريطة.
- انتهاء صلاحية OTP (60 ثانية) → زر "إعادة الإرسال" يظهر مع عدّاد تنازلي.
- الفرع الأقرب مغلق حالياً → إشعار "أقرب فرع مفتوح على بعد X كم" + خيار التبديل.

---

### 2. المسار الأساسي — طلب توصيل (Happy Path)
```
[الرئيسية] → [تصفح فئة] → [تفاصيل الصنف]
   → [اختيار الحجم/الإضافات] → [إضافة للسلة] (Bottom Sheet تأكيد)
        ◇ إضافة المزيد؟
           ├─ نعم → [رجوع للمنيو]
           └─ لا  → [فتح السلة]
   → [مراجعة السلة] → [اختيار "توصيل"]
   → [اختيار العنوان] ◇ يوجد عنوان محفوظ؟
        ├─ نعم → [تأكيد العنوان]
        └─ لا  → [إضافة عنوان جديد بالخريطة] → [تأكيد]
   → [اختيار وقت التوصيل: فوري/مجدول]
   → [إدخال كوبون] ◇ صالح؟
        ├─ نعم → [تطبيق الخصم]
        └─ لا  → [رسالة خطأ + متابعة بدون كوبون]
   → [اختيار طريقة الدفع: كاش/بطاقة/محفظة]
   → [مراجعة نهائية للطلب] → [تأكيد الطلب]
   → [شاشة نجاح] → [التتبع اللحظي]
        (تحديث تلقائي للحالة: استُلم ← قيد التحضير ← في الطريق ← تم التسليم)
   → [إشعار push عند التسليم] → [شاشة التقييم] → [End]
```
**حالات استثنائية:**
- نفاد صنف أثناء التصفح → شارة "غير متوفر حالياً" رمادية + تعطيل زر الإضافة.
- فشل الدفع بالبطاقة → رسالة واضحة + العودة لخطوة الدفع دون فقد السلة.
- الفرع خارج نطاق التوصيل للعنوان المُدخل → اقتراح فرع بديل أو التحويل لـ"استلام".

---

### 3. مسار الاستلام من الفرع (Pickup)
```
[السلة] → [اختيار "استلام من الفرع"] → [اختيار الفرع] (خريطة + قائمة)
   → [اختيار وقت الاستلام] → [الدفع] → [تأكيد الطلب]
   → [شاشة "طلبك قيد التحضير" + رقم مرجعي]
        ◇ العميل وصل الفرع؟
           └─ [عرض رقم الطلب للموظف] → [استلام الطلب] → [تقييم] → [End]
```
**حالة استثنائية:** العميل يصل قبل جاهزية الطلب → الشاشة تعرض تقدير الوقت المتبقي لحظياً.

---

### 4. مسار الحجز للتناول بالفرع (Dine-in Reservation)
```
[الرئيسية] → [الحجوزات] → [اختيار الفرع]
   → [اختيار التاريخ] → [اختيار الوقت] ◇ يوجد مواعيد متاحة؟
        ├─ نعم → [اختيار عدد الأفراد] → [ملاحظات إضافية] → [تأكيد الحجز]
        └─ لا  → [اقتراح أقرب وقت متاح] أو [اقتراح فرع آخر]
   → [شاشة تأكيد + رقم الحجز] → [إضافة تذكير للتقويم]
   → (قبل الموعد بساعة) [إشعار تذكير] → [End]
```
**حالات استثنائية:** إلغاء الحجز خلال أقل من ساعتين من الموعد → تحذير "قد يؤثر على أولوية حجوزاتك القادمة" (سياسة تحدَّد لاحقاً مع العميل).

---

### 5. مسار إعادة الطلب بضغطة واحدة (Reorder)
```
[سجل الطلبات] → [اختيار طلب سابق] → [عرض التفاصيل]
   → [زر "اطلب نفس الطلب"]
        ◇ كل الأصناف متاحة حالياً؟
           ├─ نعم → [إضافة الكل للسلة] → [Checkout مباشرة]
           └─ لا  → [عرض قائمة: متاح/غير متاح] → [إضافة المتاح فقط] → [Checkout]
```

---

### 6. مسار تطبيق كوبون / استبدال نقاط الولاء
```
[Checkout] → [إدخال كود كوبون] أو [فتح "نقاط الولاء" → اختيار مكافأة]
   ◇ الشروط مستوفاة؟ (حد أدنى للطلب / صنف مؤهل / تاريخ الصلاحية)
      ├─ نعم → [تطبيق الخصم على الإجمالي] → [متابعة الدفع]
      └─ لا  → [رسالة توضح سبب الرفض تحديداً] (مثال: "الكوبون يتطلب حد أدنى 200 ج.م")
```

---

### 7. مسار إدارة العناوين
```
[الملف الشخصي] → [العناوين المحفوظة] → [إضافة عنوان جديد]
   → [تحديد الموقع بالخريطة أو GPS] → [تسمية العنوان: المنزل/العمل/أخرى]
   → [تفاصيل إضافية: رقم الشقة، الدور، علامة مميزة] → [حفظ]
   ◇ أول عنوان يُضاف؟
      └─ نعم → [تعيينه تلقائياً كافتراضي]
```
**تعديل/حذف:** سحب العنوان (Swipe) يظهر خياري تعديل وحذف؛ حذف العنوان الافتراضي يطلب اختيار بديل فوري.

---

### 8. مسار إلغاء الطلب
```
[تفاصيل الطلب] → [زر "إلغاء الطلب"]
   ◇ حالة الطلب؟
      ├─ "قيد المراجعة" (أقل من 5 دقائق من الطلب) → [إلغاء فوري بدون رسوم] → [استرداد كامل]
      ├─ "قيد التحضير" → [تحذير: قد تُطبَّق رسوم] → ◇ تأكيد؟
      │      ├─ نعم → [إرسال طلب الإلغاء للفرع] → [انتظار موافقة الفرع]
      │      └─ لا  → [رجوع للطلب]
      └─ "في الطريق" أو "تم التسليم" → [الإلغاء غير متاح] → [توجيه لمسار الدعم/الشكوى]
```

---

### 9. مسار الدعم والشكاوى
```
[تفاصيل الطلب] → [زر "لدي مشكلة"] → [اختيار نوع المشكلة]
   (نقص في الطلب / صنف خاطئ / تأخير / جودة / أخرى)
   → [رفع صورة (اختياري)] → [إرسال التذكرة]
   ◇ نوع المشكلة يسمح بحل تلقائي؟ (مثال: تأخير > 45 دقيقة)
      ├─ نعم → [عرض تعويض تلقائي: كوبون اعتذار] → [End]
      └─ لا  → [تحويل لفريق الدعم البشري] → [دردشة مباشرة/اتصال] → [متابعة الحالة]
```

---

### 10. مسار الزائر (Guest) مقابل الحساب المسجَّل
```
[فتح التطبيق لأول مرة] ◇ يريد التصفح فقط أم الطلب؟
   ├─ تصفح فقط → [الدخول كزائر] → [تصفح كامل المنيو والفروع بدون قيود]
   └─ يريد الطلب → عند الوصول لـ Checkout:
        ◇ لديه حساب؟
           ├─ نعم → [تسجيل الدخول] → [استكمال الطلب]
           └─ لا  → [إنشاء حساب سريع (رقم + OTP فقط، بدون بريد إلكتروني إجباري)] → [استكمال الطلب]
```
**ملاحظة تصميم:** لا يُطلب تسجيل الدخول إجبارياً عند فتح التطبيق — فقط عند لحظة الحاجة الفعلية (الدفع)، لتقليل الاحتكاك (Friction) وزيادة معدل التحويل.

---

## قسم ب) مسارات لوحة تحكم الإدارة

### 11. مسار العمليات اليومية لمدير الفرع
```
[تسجيل الدخول] → [لوحة التحليلات] (نظرة سريعة: طلبات اليوم، الإيراد، تنبيهات)
   → [لوحة الطلبات اللحظية] ◇ يوجد طلب معلّق أكثر من الوقت المتوقع؟
      ├─ نعم → [تنبيه بصري/صوتي] → [فتح الطلب] → [تحديث الحالة يدوياً أو التواصل مع العميل]
      └─ لا  → [استمرار المتابعة الروتينية]
   → [سحب/إفلات بطاقة الطلب بين أعمدة الحالة: جديد ← قيد التحضير ← جاهز ← تم التسليم]
   → (نهاية اليوم) [مراجعة تقرير المبيعات اليومي] → [End]
```

---

### 12. مسار إنشاء ونشر صنف جديد في المنيو
```
[إدارة المنيو] → [إضافة صنف جديد] → [إدخال الاسم AR/EN + الوصف + الصور]
   → [تحديد الفئة] → [تحديد السعر (وأحجام إن وجدت)] → [ربط مجموعات الإضافات]
   → [تحديد الفروع المتاح بها الصنف] → [حفظ كمسودة]
   ◇ جاهز للنشر؟
      ├─ نعم → [نشر] → [ظهور فوري في تطبيق العملاء بالفروع المحددة]
      └─ لا  → [يبقى Draft غير ظاهر للعملاء]
```

---

### 13. مسار مراجعة أداء الفروع (مدير عام/Super Admin)
```
[لوحة التحليلات] → [مقارنة أداء الفروع] → [ترتيب حسب: المبيعات/عدد الطلبات/التقييم]
   ◇ فرع أداؤه منخفض بشكل ملحوظ؟
      ├─ نعم → [فتح تفاصيل الفرع] → [مراجعة التقييمات والشكاوى المرتبطة]
      │        → [إجراء: تواصل مع مدير الفرع / تعديل عرض ترويجي مخصص للفرع]
      └─ لا  → [تصدير التقرير الأسبوعي] → [End]
```

---

### 14. مسار معالجة شكوى عميل واسترداد
```
[صندوق تذاكر الدعم] → [فتح تذكرة جديدة] → [مراجعة تفاصيل الطلب المرتبط]
   ◇ الشكوى مبررة؟
      ├─ نعم → [اختيار الإجراء: استرداد كامل/جزئي، كوبون تعويض، اعتذار فقط]
      │        → [تنفيذ الإجراء] → [إشعار العميل تلقائياً] → [إغلاق التذكرة]
      └─ لا  → [الرد بتوضيح مع الحفاظ على نبرة احترافية ودافئة] → [إغلاق التذكرة]
```

---

### 15. مسار إطلاق حملة ترويجية
```
[التسويق] → [إنشاء كوبون جديد] → [تحديد: نوع الخصم، الحد الأدنى، الصلاحية، الفروع المشمولة]
   → [حفظ الكوبون] → [إنشاء حملة إشعارات Push مرتبطة]
   → [تحديد شريحة العملاء المستهدفة] (الكل / عملاء غير نشطين / عملاء VIP)
   → [جدولة وقت الإرسال] → [معاينة الرسالة] → [إرسال/جدولة]
   → [متابعة معدل الاستخدام من لوحة التحليلات] → [End]
```

---

### 16. مسار إضافة موظف جديد وتحديد صلاحياته
```
[الموظفون والصلاحيات] → [إضافة موظف جديد] → [بيانات الموظف الأساسية]
   → [تحديد الدور: Super Admin / مدير فرع / موظف / دعم]
   ◇ الدور = مدير فرع أو موظف؟
      ├─ نعم → [ربط الموظف بفرع/فروع محددة]
      └─ لا (Super Admin) → [صلاحية كاملة على كل الفروع تلقائياً]
   → [إرسال دعوة عبر البريد/SMS لتفعيل الحساب] → [End]
```
